1. INTRODUCTION                                         *mermaid-introduction*

Syntax highlighting, indentation and filetype support for mermaid diagram
files. See https://mermaid.js.org for the language itself.

Both `filetype plugin indent on` and `syntax enable` must be active in your
vimrc; neither is set by the plugin.

==============================================================================
2. FILETYPE DETECTION                                       *mermaid-filetype*

The `mermaid` filetype is set for `*.mmd`, `*.mermaid` and `*.mm`.

                                                        *g:mermaid_detect_mm*
`*.mm` is ambiguous: Vim's own runtime maps it to objcpp or nroff, and this
plugin overrides that. To keep Vim's behaviour instead: >
    let g:mermaid_detect_mm = 0
<

3. DIAGRAM TYPES                                       *mermaid-diagram-types*

The recognised openers are taken from the detector regexes in mermaid's own
source rather than from its documentation site, which lags behind:
>
    agentflow-beta      gitGraph            railroad-peg-beta
    architecture        graph               requirementDiagram
    block               info                sankey
    C4Component         ishikawa            sequenceDiagram
    C4Container         journey             stateDiagram
    C4Context           kanban              stateDiagram-v2
    C4Deployment        mindmap             swimlane-beta
    C4Dynamic           packet              timeline
    classDiagram        pie                 treemap
    classDiagram-v2     quadrantChart       treeView-beta
    cynefin-beta        radar-beta          usecase-beta
    erDiagram           railroad-beta       venn-beta
    eventmodeling       railroad-abnf-beta  wardley-beta
    flowchart           railroad-ebnf-beta  xychart
    flowchart-elk       gantt               zenuml
<
Several types dropped their `-beta` suffix upstream but still accept it, so
both spellings are recognised: `architecture`, `block`, `ishikawa`, `packet`,
`sankey`, `treemap` and `xychart`.

Bare `requirement` is a valid opener but is highlighted as a keyword, because
`requirement r1 {` inside a requirementDiagram is the far more common use.

==============================================================================
4. INDENTATION                                                *mermaid-indent*

'shiftwidth' controls the step. A block is opened by a diagram declaration
(`graph`, `sequenceDiagram`, ...), by `subgraph`, `loop`, `alt`, `else`,
`opt`, `par`, `and`, `rect`, `critical`, `option`, `break`, `box`,
`namespace`, `activate`, and by a `class`/`state`/`namespace` line ending in
`{`. It is closed by `end`, `}`, `deactivate`, and by the branch keywords
`else`, `and` and `option`, which close and reopen at the same level.

Typing a diagram declaration on an indented line moves it back to column 0.

Diagrams where indentation carries meaning are never reflowed: `=` leaves them
untouched and a new line inherits the indent of the line above it. That covers
`mindmap`, `ishikawa`, `treemap` and `treeView-beta`, which nest by indent, and
`sankey`, `packet` and `timeline`, which gain nothing from being reflowed.

`block:ID` and `requirement r1 {` share their keyword with a diagram
declaration but open a block inside one, so they are not pulled to column 0.

5. HIGHLIGHT GROUPS                                        *mermaid-highlight*

Every group is linked with `highlight default link`, so a colorscheme or your
vimrc can override any of them: >
    highlight link mermaidDiagramType Special
<
The groups are named after the construct they cover, for example
`mermaidDiagramType`, `mermaidKeyword`, `mermaidComment`, `mermaidString`,
`mermaidNodeLabel`, `mermaidGraphOperator`, `mermaidErOperator`,
`mermaidClassFunction`, `mermaidGanttKeyword`, `mermaidGitCommands`. Run
`:syntax list` inside a mermaid buffer for the full set.

6. TESTING                                                   *mermaid-testing*

The suite runs headlessly against both editors, with no dependencies: >
    ./test/run.sh                    # vim
    EDITOR_BIN=nvim ./test/run.sh    # neovim
    ./test/run.sh indent_spec.vim    # a single spec
<
